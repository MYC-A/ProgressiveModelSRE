# Сравнение архитектур для SRE

7 ноября 2026. Результаты реальных локальных запусков.

## Основные результаты

На текущем синтетическом SRE-пилоте наибольшая средняя точность у **Qwen3.5 + schema numeric executor: 88.9%**. Это максимум точности на данном тесте, а не автоматически лучший эксплуатационный режим: ложные тревоги, пропуски и unknown приведены отдельно.

Qwen3.5 без исполнителя правильно классифицировала 280/288 определённых исходов, но 0/144 случаев unknown. С числовым исполнителем правильно все 288 определённых исходов и 96/144 unknown; остальные 48 неопределённых случаев названы failure. Поэтому ноль ошибок на известных success/failure не означает надёжность полного решения.

На прямой вопрос о равенстве 200 и 200 Qwen3 начинает ответ с Yes, а Qwen3.5 — с No; обе добавляют пояснение сверх короткого формата. Замена архитектуры не устранила все исходные симптомы.

На реальном BGL все небольшие прототипы работают за единицы миллисекунд на окно, но при основном пороге пропускают существенную часть тревог. Готовой универсальной архитектуры, подтверждённой этим исследованием, нет.

Результат поддерживает дальнейшую проверку разделения текстовой обработки и явного исполнения числовых условий. Для последовательностей нужны собственные проверки порядка событий; результат классификации окна не заменяет их.

Графики: [SRE](figures/sre.png), [BGL](figures/bgl.png). Оборудование: AMD Ryzen 7 5825U, 16 ГиБ RAM, CPU, 4 потока. Все готовые языковые модели запускались в FP32, без квантования.

## Что именно проверено

Две задачи оцениваются отдельно: применение заданного критерия к тексту и бинарная классификация окон реальных логов BGL. Модели с предобучением, обучение с нуля и системы с исполнителем не являются контролируемым сравнением только архитектуры.

- **SRE:** 1080 синтетических обучающих, 216 валидационных и 432 тестовых примера. В тесте по 144 success/failure/unknown. Для числовых семейств диапазоны разделены; формулировки свидетельств success/failure меняются по выборкам. Часть критериев, служебных фраз и шаблонов unknown общая. Полного прежнего набора 120 примеров локально нет.
- **BGL:** исходный полный файл проверен по контрольной сумме Loghub/Zenodo. Из него до обучения выбраны непересекающиеся окна по 32 строки: 3000/800/1000 окон по хронологическим частям 60%/20%/20%. В тесте 77 окон с тревогами и 923 нормальных. Это пилот на выборке, не повтор прежнего полного BGL-бенчмарка.
- **CPU:** 4 потока на общем рабочем компьютере; тёплая задержка одного запроса включает токенизацию/признаки, вычисление и разбор ответа. Это не SLA сервера. Холодная загрузка моделей в эти миллисекунды не входит. Измерены первые 24/30 тестовых случаев, а не весь поток; смесь быстрых и медленных ветвей в этом поднаборе может отличаться от смеси во всей выборке. По этим данным не оценивается средняя пропускная способность промышленного потока.

## Применение критериев: SRE

Числа ошибок для обучаемых вариантов показаны диапазоном по трём seed. Задержка — медиана измеренных p95 по seed; для генеративных моделей один запуск. Нарушения формата считаются ошибками. Пропуск сбоя здесь включает ответ unknown; это отличается от ложного утверждения success и отдельно разобрано ниже.

Для ModernBERT заморожен весь энкодер, обучается только MLP-голова. Это не проверка полного дообучения ModernBERT. Вариант с числовыми признаками получает результаты ограниченного парсера и отношений чисел; guarded-вариант исполняет эти отношения явно. Парсер знает грамматику синтетических входов, поэтому его успех не доказывает универсальное понимание новых логов.

Qwen3.5 + executor применяет тот же ограниченный числовой парсер, а нечисловые случаи передаёт Qwen3.5. Это отдельная гибридная система. Поле `baseline_output_text` хранит исходный ответ языковой модели; `system_output` — итог после маршрутизации и сравнения.

FLAN extraction выполняет настоящие отдельные вызовы извлечения actual и expected и затем сравнивает числа. Операторы распознаются ограниченной схемой, привязка извлечённого значения к объекту и времени независимо не доказана. Входные поля генератора с правильными actual/expected моделям не передавались.

## Окна реального BGL

Все малые сети используют одинаковые признаки сообщений и временного разрыва. Исходная метка и поле severity исключены из входа. Обучение с весами классов; порог — 99-й процентиль оценок нормальных окон валидации, решение по строгому `>`. Целевые 1% на валидации не гарантируют такой же FPR на будущем потоке.

| Архитектура | Запусков | Recall тревог, % | Ложные тревоги /923 | Пропуски /77 | p95, мс |
|---|---:|---:|---:|---:|---:|
| Всегда «норма» | — | 0 | 0 | 77 | — |
| GNN, temporal edges | 3 | 55.8–72.7 | 4–27 | 21–34 | 1.73 |
| GRU | 3 | 55.8–72.7 | 4–21 | 21–34 | 1.90 |
| LSTM | 3 | 57.1–66.2 | 13–43 | 26–33 | 1.36 |
| Pooled features + MLP | 3 | 26.0–68.8 | 11–17 | 24–57 | 1.04 |
| Selective SSM / SSD reference | 3 | 55.8–76.6 | 2–13 | 18–34 | 2.22 |
| TCN | 3 | 64.9–68.8 | 2–25 | 24–27 | 2.13 |

Глобальный порядок BGL смешивает узлы; граф здесь построен по соседству событий в окне и не является графом причинности сервисов. Метка окна означает наличие хотя бы одной размеченной тревоги. Это не отдельная проверка предсказания следующего события и не доказательство, что сеть выучила порядок исполнения. Результаты перестановки событий сохранены в `shuffled_metrics`. BGL не содержит эталонного класса unknown.

Дополнительные пороги с бюджетами 0,5/1/3/5% FPR выбраны по нормальным окнам валидации и сохранены в `stream_operating_points.json`. Это дополнительная диагностика после первичных результатов; тестовые метки для выбора порогов не используются.

## Пределы вывода

- Малые GRU/LSTM/TCN/SSM обучены с нуля в ограниченном бюджете; провал не доказывает непригодность семейства при большем обучении.
- SSM — наша небольшая CPU-реализация input-dependent state-space recurrence по SSD. Параллельная формула проверена против независимой рекуррентной. Это не официальный предобученный Mamba-2; здесь используется плотная квадратичная референсная реализация, поэтому промышленную скорость Mamba по ней оценивать нельзя.
- Готовые языковые модели существенно различаются предобучением. Их сравнение выбирает кандидатов для задачи, а не изолирует эффект архитектуры.
- Qwen3.5 на этом CPU использует референсные PyTorch-реализации causal conv и gated delta rule: ускоренные GPU-ядра недоступны. Его измеренная задержка относится к этой реализации, не к оптимальному серверному движку.
- Числа, формулировки и область синтетического теста ограничены. Преобразование единиц, произвольные новые правила и весь промышленный поток этим пилотом не подтверждены. Ноль ошибок на малой выборке не является гарантией.
